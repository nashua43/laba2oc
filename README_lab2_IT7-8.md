## 1. Назначение программы

Программа предназначена для изучения многопоточного умножения матриц, распределения вычислительной нагрузки между потоками и обмена данными между отдельными процессами.

В проекте реализованы:

- умножение двух прямоугольных матриц с использованием нескольких потоков;
- распределение строк результирующей матрицы между рабочими потоками;
- отображение хода вычислений и подсчёт завершённых строк;
- генерация исходных матриц в отдельном процессе и передача данных родительскому процессу через канал;
- умножение нижнетреугольной матрицы на обычную матрицу;
- компактное ступенчатое хранение нижнетреугольной матрицы;
- статическое и динамическое распределение строк;
- проверка параллельных результатов сравнением с последовательным алгоритмом;
- измерение времени выполнения и сохранение результатов экспериментов в CSV-файл.

## 5. Запуск программы

Общий формат запуска:

```bash
java -cp out lab2.Main РЕЖИМ ПАРАМЕТРЫ
```

Доступны следующие режимы.

### 5.1. Обычное умножение матриц

```bash
java -cp out lab2.Main multiply n m k T
```

Параметры:

- `n` — количество строк матрицы A;
- `m` — количество столбцов матрицы A и строк матрицы B;
- `k` — количество столбцов матрицы B;
- `T` — количество рабочих потоков.

Пример:

```bash
java -cp out lab2.Main multiply 500 400 300 4
```

В этом примере матрица A имеет размер 500 × 400, матрица B — 400 × 300, а результат C — 500 × 300. Программа выводит прогресс, время вычисления, количество завершённых строк и контрольную сумму. Для небольшого результата размером не более 10 × 10 дополнительно печатается вся матрица.

### 5.2. Генерация матриц отдельным процессом (IPC)

```bash
java -cp out lab2.Main ipc n m k T
```

Пример:

```bash
java -cp out lab2.Main ipc 500 400 300 4
```

В этом режиме `Main` запускает отдельный процесс Java с помощью `ProcessBuilder`. Дочерний процесс `GeneratorProcess` генерирует матрицы A и B. Сначала он передаёт размеры матриц, затем их элементы в бинарном формате через `stdout`. Родительский процесс читает данные из потока и восстанавливает массивы.

Служебные сообщения дочернего процесса направляются в `stderr`, поскольку `stdout` используется как канал передачи данных. В консоли отдельно отображается время генерации и передачи матриц, после чего выполняется их параллельное умножение.

### 5.3. Нижнетреугольная матрица: статическое распределение

```bash
java -cp out lab2.Main triangle n T static
```

Пример:

```bash
java -cp out lab2.Main triangle 500 4 static
```

Строки результата заранее делятся на непрерывные блоки. Каждый поток обрабатывает назначенный ему диапазон строк.

### 5.4. Нижнетреугольная матрица: динамическое распределение

```bash
java -cp out lab2.Main triangle n T dynamic
```

Пример:

```bash
java -cp out lab2.Main triangle 500 4 dynamic
```

В динамическом режиме поток получает следующую свободную строку с помощью атомарного счётчика `AtomicInteger`. Это позволяет распределять строки по мере освобождения потоков.

### 5.5. Справка

Для вывода доступных режимов выполните:

```bash
java -cp out lab2.Main help
```

## 6. Особенности реализации

### 6.1. Алгоритм умножения

Если матрица A имеет размер `n × m`, а матрица B — `m × k`, то результат C имеет размер `n × k`. Каждый элемент результата вычисляется по формуле:

```text
C[i][j] = A[i][0] * B[0][j] + ... + A[i][m-1] * B[m-1][j]
```

В программе используется ручное умножение с вложенными циклами. Порядок циклов — `i → p → j`. Матрицы хранятся в двумерных массивах типа `long[][]` и заполняются целыми случайными числами от 0 до 9.

### 6.2. Многопоточность и синхронизация

Рабочие потоки создаются вручную с помощью класса `Thread`. При статическом распределении количество строк делится на количество потоков. Остаток распределяется по одной дополнительной строке между первыми потоками.

Каждый поток записывает результат только в назначенные ему строки матрицы C. Общая матрица результата не требует блокировки при записи, так как потоки работают с непересекающимися строками.

Для подсчёта завершённых строк применяется `AtomicInteger`. Главный поток ожидает окончания вычислений с помощью `join()` и выводит процент готовности.

### 6.3. Нижнетреугольная матрица и экономия памяти

В нижнетреугольной матрице все элементы выше главной диагонали равны нулю. Поэтому строка с индексом `i` содержит только `i + 1` значимых элементов. В программе A хранится в ступенчатом массиве: длина строки `i` равна `i + 1`.

Количество хранимых элементов составляет:

```text
n * (n + 1) / 2
```

Вместо `n²` элементов полной квадратной матрицы. При вычислении строки `i` достаточно перебирать индекс `p` от 0 до `i`, поскольку остальные элементы этой строки равны нулю.

### 6.4. Межпроцессное взаимодействие и альтернативы

В данной реализации используется канал между стандартными потоками дочернего и родительского процессов (`stdout` дочернего процесса читается родительским процессом). Для запуска отдельной JVM применяется `ProcessBuilder`.

Возможные способы межпроцессного взаимодействия:

| Способ | Принцип работы | Особенности |
|---|---|---|
| Каналы (pipe) | Передача последовательности байтов между связанными процессами. | Удобны для потоковой передачи данных; необходимо согласовать формат сообщений. |
| Файлы | Один процесс записывает данные, другой считывает их из файла. | Просты для отладки и хранения, но требуют операций с файловой системой. |
| Сетевые сокеты | Обмен данными через сетевое соединение. | Подходят для взаимодействия процессов на разных компьютерах; требуется настройка соединения. |
| Отображаемые в память файлы | Несколько процессов получают доступ к одному отображённому файлу. | Подходят для больших объёмов данных; требуют аккуратной синхронизации доступа. |

## 7. Проверка корректности

После параллельного умножения программа выполняет последовательное умножение тех же входных матриц и сравнивает результаты поэлементно. Проверка проводится в режимах `multiply`, `ipc`, `triangle static` и `triangle dynamic`.

В выводе успешного запуска появляется сообщение:

```text
Проверка с последовательным алгоритмом: успешно.
```

Контрольная сумма — сумма всех элементов результирующей матрицы. Она используется как дополнительная краткая характеристика результата; сама по себе контрольная сумма не заменяет поэлементное сравнение.

## 8. Проведение эксперимента

Для сравнения статического и динамического распределения используется `Benchmark.java`.

Параметры полной серии:

- размеры квадратных матриц: `500 × 500`, `1000 × 1000`, `1500 × 1500`;
- количество повторов для каждой комбинации: 5;
- число потоков: от 1 до `2 ×` количества доступных логических процессоров, а также дополнительные значения `4 ×` и `8 ×` количества доступных логических процессоров;
- для каждого набора входных данных выполняются оба режима распределения: `static` и `dynamic`.

Для каждой матрицы входные данные создаются один раз и используются обоими режимами, поэтому сравнение проводится на одинаковых A и B. Перед измеряемым вычислением выполняется прогревочный запуск, который не включается в результат. Время измеряется методом `System.nanoTime()`; в замер входят создание рабочих потоков, вычисление и ожидание их завершения. Вывод прогресса в бенчмарке отключён.

### Быстрая проверка бенчмарка

```bash
java -cp out lab2.Benchmark --quick
```

Быстрый режим использует небольшие матрицы и два повтора. Он нужен только для проверки запуска программы и структуры CSV-файла. Его результаты не следует использовать как итоговые экспериментальные данные.

### Полный бенчмарк

```bash
java -cp out lab2.Benchmark
```

Полная серия может выполняться продолжительное время. По окончании в корневой папке проекта создаётся файл `triangle_benchmark.csv`.

В CSV записываются следующие столбцы:

| Столбец | Значение |
|---|---|
| `size` | Размер стороны квадратной матрицы. |
| `threads` | Количество рабочих потоков. |
| `distribution` | Тип распределения: `static` или `dynamic`. |
| `run` | Номер повтора. |
| `time_seconds` | Время вычисления в секундах. |
| `checksum` | Контрольная сумма результата. |

## 9. Обработка и анализ результатов

Для каждой комбинации размера матрицы и числа потоков следует сравнить среднее время статического и динамического распределения. Среднее время рассчитывается по пяти повторам.

Для оценки параллельного ускорения можно использовать формулы:

```text
S(T) = t(1) / t(T)
E(T) = S(T) / T
```

где:

- `t(1)` — время выполнения при одном потоке;
- `t(T)` — время выполнения при T потоках;
- `S(T)` — ускорение;
- `E(T)` — эффективность.

Вывод о том, какой способ распределения быстрее, необходимо делать по результатам полного эксперимента на конкретном компьютере. Нельзя заранее считать статический или динамический способ лучшим для всех размеров матриц.
