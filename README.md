## 1. Что реализовано

- Ручное умножение прямоугольных матриц `A(n × m)` и `B(m × k)` вложенными циклами.
- Создание рабочих потоков через `Thread`, ручное распределение непрерывных блоков строк.
- Общий счётчик завершённых строк `AtomicInteger`, вывод прогресса и ожидание потоков через `join()`.
- Полная матрица результата `C` хранится в памяти; выводится контрольная сумма.
- Генерация матриц отдельной JVM через `ProcessBuilder` и передача бинарных данных по каналу `stdout` дочернего процесса → `stdin` родительского процесса.
- Нижнетреугольная матрица `A` хранится ступенчато: в строке `i` только `i + 1` элементов, нули выше диагонали не хранятся.
- Статическое и динамическое распределение строк. В динамическом режиме строка выдаётся через `AtomicInteger.getAndIncrement()`.
- Последовательная реализация для проверки результатов; параллельные результаты в основных режимах сравниваются поэлементно.
- Отдельные бенчмарки обычного умножения, сравнения `static/dynamic` и IPC. CSV сохраняется после каждой строки замера.

Сторонние библиотеки для умножения матриц, Maven и Gradle не используются.

## 5. Запуск программы

Общий формат:

```text
java -cp out lab2.Main РЕЖИМ ПАРАМЕТРЫ
```

### 5.1. Обычное умножение матриц

```powershell
java -cp out lab2.Main multiply 500 400 300 4
```

Аргументы: `n` — строки A; `m` — столбцы A и строки B; `k` — столбцы B; `T` — количество потоков. Каждый поток получает свой непрерывный блок строк результата. Прогресс обновляется по завершённым строкам. Время измеряется `System.nanoTime()` после генерации матриц.

### 5.2. Генерация матриц отдельным процессом (IPC)

```powershell
java -cp out lab2.Main ipc 500 400 300 4
```

Родительская JVM запускает `GeneratorProcess` через `ProcessBuilder`. Дочерний процесс сначала передаёт три размера матриц, затем значения `long` через `DataOutputStream`. Родитель читает их через `DataInputStream`. Поток ошибок дочернего процесса не смешивается с бинарным потоком.

Программа отдельно показывает время запуска дочерней JVM, генерации матриц, чтения полезных данных из канала и последующего умножения. Время чтения по каналу измеряется отдельно от генерации; оно включает ожидание данных, если отправитель ещё не успел их записать.

### 5.3. Нижнетреугольная матрица — static

```powershell
java -cp out lab2.Main triangle 500 4 static
```

Каждому потоку заранее назначается непрерывный диапазон строк. При делении остаток распределяется по одной дополнительной строке первым потокам.

### 5.4. Нижнетреугольная матрица — dynamic

```powershell
java -cp out lab2.Main triangle 500 4 dynamic
```

Потоки получают следующую свободную строку через `AtomicInteger.getAndIncrement()`. Поскольку нижние строки требуют больше операций, динамическая выдача может уменьшить дисбаланс нагрузки, но сама операция получения строки тоже имеет накладные расходы.

## 6. Как устроено умножение и синхронизация

Для обычных матриц:

```text
C[i][j] = сумма(A[i][p] * B[p][j]), p = 0 ... m-1
```

Используется порядок циклов `i → p → j`. Внутренний цикл последовательно проходит элементы строки B и строки C.

Потоки создаются вручную через `new Thread(...)`. Каждый поток пишет только в принадлежащие ему строки C, поэтому блокировка матрицы результата не нужна. Главный поток ждёт завершения рабочих потоков через `join()`.

После вычисления строки поток вызывает `completed.incrementAndGet()`. Операция атомарная: без синхронизации два потока могли бы одновременно прочитать старое значение счётчика и потерять одно из увеличений. Для результата блокировка не нужна, поскольку диапазоны строк не пересекаются.

## 7. IPC: выбранный способ и альтернативы

Выбран анонимный канал между родительским и дочерним процессами. Канал представляет собой поток байтов: родитель читает данные по мере их поступления. Если получатель читает медленнее, буфер канала заполняется, и запись со стороны отправителя блокируется до появления места. Границы матриц задаются заголовком из трёх целых размеров, затем следует фиксированное количество значений `long`; после чтения ожидаемого числа элементов передача считается завершённой. Дополнительный общий счётчик для канала не нужен: порядок байтов сохраняется, а завершение дочернего процесса проверяется отдельно.

Бинарный формат выбран потому, что значения передаются компактно и не требуют преобразования каждого числа в текст и обратно.

| Способ IPC | Принцип | Преимущества | Ограничения |
|---|---|---|---|
| Анонимный канал (pipe), используется в проекте | Поток байтов между связанными процессами | Простая потоковая передача, порядок байтов сохраняется | Обычно связан с родительским/дочерним процессом; нужно согласовать формат |
| Файл | Один процесс записывает данные, другой читает | Просто отлаживать, данные можно сохранить | Операции с диском, управление временным файлом и моментом готовности |
| Сетевой сокет | Обмен по сетевому соединению | Работает между разными компьютерами | Нужно устанавливать соединение, обрабатывать ошибки сети и протокол |
| Разделяемая память / отображаемый файл | Несколько процессов обращаются к общей области памяти | Подходит для больших объёмов, меньше копирования данных | Нужны средства синхронизации и согласование доступа |
| Очередь сообщений | Передача отдельных сообщений через системную очередь | Есть логические границы сообщений, процессы не обязаны запускаться одновременно | Ограничения размера/числа сообщений и системные накладные расходы |

## 8. Нижнетреугольная матрица и распределение строк

В нижнетреугольной матрице все элементы выше главной диагонали равны нулю. Они не создаются и не хранятся. Строка с индексом `i` содержит `i + 1` элементов, всего хранится `n(n + 1)/2` элементов вместо `n²`.

Элемент результата:

```text
C[i][j] = сумма(A[i][p] * B[p][j]), p = 0 ... i
```

Последняя строка требует больше операций, чем первая. Поэтому статическое деление по количеству строк может давать неравную вычислительную нагрузку. Динамический способ выдаёт строки по мере освобождения потоков. Оба способа записывают результат в общую матрицу C, каждый поток отвечает за свою строку.

## 9. Эксперименты и CSV

Полная серия для обычного умножения (оценка «3»):

```powershell
java -cp out lab2.Benchmark
```

- размеры: `500 × 500`, `1500 × 1500`, `3000 × 3000`;
- пять повторов для каждой пары «размер — число потоков»;
- количество потоков: все значения `1..2L`, затем `4L` и `8L`, где `L = Runtime.getRuntime().availableProcessors()`;
- перед каждым измерением выполняется неучитываемый прогревочный запуск;
- время включает запуск рабочих потоков, вычисление и ожидание их завершения; генерация и подсчёт контрольной суммы не входят;
- CSV содержит исходные пять измерений; при анализе отбрасываются минимальное и максимальное значения, три оставшихся усредняются.

Результат: `matrix_benchmark.csv`.

Серия для нижнетреугольной матрицы (дополнение оценки «4»):

```powershell
java -cp out lab2.Benchmark triangle
```

Используются те же размеры, значения числа потоков и пять повторов. Для каждой комбинации выполняются `static` и `dynamic` на одинаковых входных данных. Результат: `triangle_benchmark.csv`.

Сравнение затрат IPC и умножения:

```powershell
java -cp out lab2.Benchmark ipc 12
```

Последний аргумент — число потоков для умножения. Выполняются размеры `500`, `1500`, `3000`; результат сохраняется в `ipc_benchmark.csv`. В CSV отдельно записаны время запуска процесса, генерации, получения данных по каналу, суммарное время получения матриц и время умножения.

### Быстрые проверки

```powershell
java -cp out lab2.Benchmark --quick
java -cp out lab2.Benchmark triangle --quick
```

Быстрые серии используют матрицы 20 и 40 и два повтора. Они проверяют запуск и формат CSV, но **не являются экспериментальными результатами для отчёта**.

Все CSV-файлы обновляются после каждой строки, поэтому завершённые замеры сохраняются при остановке процесса. Прерванная серия неполная и не подходит для итоговых таблиц.

## 10. Построение графиков

Установите matplotlib:

```powershell
py -m pip install matplotlib
```

Построение всех доступных графиков:

```powershell
py plot_results.py --physical-cores 8 --logical-processors 12
```

Числа `8` и `12` здесь только пример. Перед построением замените их на фактические характеристики своего процессора. Если не указывать параметры, графики построятся без вертикальных линий ядер.

Скрипт создаёт папку `graphs` и строит:
- обычное умножение: время, ускорение и эффективность по числу потоков;
- нижнетреугольное умножение: сравнение времени `static` и `dynamic`;
- IPC: время чтения данных по каналу и время умножения для разных размеров.
